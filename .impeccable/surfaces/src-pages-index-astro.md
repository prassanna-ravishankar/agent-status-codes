# Homepage surface brief

## Scope and mode

- Target: `src/pages/index.astro`
- Mode: Replacement
- Related surfaces: interactive registry and authoritative registry Markdown

## Reader, job, and action

Framework authors and agent builders need to understand the interoperability
problem, enter the numbered code space, and reach the normative protocol. The
primary action is to browse the registry. The secondary action is to read ASC
0.1.

## Chosen direction

The approved comp is
`.impeccable/mocks/asc-astro-protocol-index.png`. It establishes an engineered
standards reference with compact navigation, a real status envelope, and the
nine code classes in the first viewport. Generated copy, fake counts, and logo
detail in the comp are not implementation requirements.

## Fidelity inventory

| Ingredient | Commitment | Medium |
|---|---|---|
| Header | Wordmark, Protocol, Registry, Implement, RFCs, search, version, source | Astro component |
| Problem | Short HTTP analogy followed by what ASC supplies | Semantic prose |
| Envelope | Real ASC 0.1 status data, not a decorative formula | Semantic code figure |
| Class index | One labeled row from 1xxx through 9xxx | Generated links from registry metadata |
| Registry | Search, class filters, deep links, authoritative fields only | Generated from `docs/spec/registry.md` |
| Documentation | Quiet three-rail reading layout on wide screens | Astro layout and Markdown |

## Constraints

ASC 0.1 remains visibly experimental. Do not invent adoption, governance,
severity, or transport mappings. Class color supports text labels and never
carries meaning alone. Keep focus visible, preserve reduced-motion and contrast
preferences, and allow reference tables to scroll on narrow screens.
